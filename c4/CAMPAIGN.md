## 1. 评分公式与 token 乘子（已拟合验证）

```
FinalScore = 100 · Accuracy · (0.7 + 0.3 · TokenScore)
TokenScore = 1 − used_tokens / 5_000_000
=> 真实准确率 = 官方分 / (100 · 乘子)
```
27b 用 686437 token → 乘子 0.9588，完美拟合（70.9522→74%）。

### ⚠️⚠️ 判分规则更正(官方明文, 推翻全篇"宽松键/部分分"假设)
**「多选题不设置部分分, 漏选/错选/多选 均计为整题错误」**——exact-match, 必须与官方答案【完全相等】才得分。

  - **over-select 会把本来精确对的题改成错** —— "只加不删"策略作废, 需逐题求精确集。
**计数仍有效**(分/乘子是乘子算术, 与判分规则无关): 11=88精确匹配题, 13=88, 12=87。

## 3. ★ 最关键发现：官方评分键【宽松】

由 235b=77 / fixed=79 / star3=76 三锚点解出（每改动效应∈{+1,0,−1}）：
- **ADD 一个逐字为真的选项 = +1**（官方照单全收）
- **REMOVE 一个选项 = −1**（官方算它真，删了白丢分）

fixed 只 +2 不是 +6，就是混进了 3 个 REMOVE。**策略：只加不删。**
推论：官方真答案 ≈「235b 答案 ∪ 漏掉的逐字真选项」。这就是 06_addonly 的构造法。

## 10. 管线架构大重构 (2026-06-26)：弃 agentic decompose+judge+verdict，回归 legacy 式合并推理

**动机**：诊断发现 agentic 的 decompose(LLM 原子化取值) 是病根——把定性/趋势/比较选项硬拆成"X是多少"数值查询，judge 抽不出→丢分；且每题 ~10 次 LLM 调用，token 乘子吃亏。验证(本地 gpt-oss, 现 PaddleOCR-VL 索引, dev 99 题 exact-match)：
- 老 agentic ~62%（high-conf 67%，~10 次 LLM/题）
- legacy(整体读证据一次答) 65%（恢复跑，仅 344k token）
- **新简化管线 71%（high-conf 71%，1-2 次 LLM/题）** ← 最优

**新架构**（`agent/agentic/decompose.py` + `solver.py`，judge/verdict 移出生产线）：
```
规则 decompose(无 LLM) → 逐 fact BM25 检索 → 合并全部 chunk → 领域 prompt 一次答题
```
1. **规则 decompose**：facts = 每选项一条(ask=选项原文) + 每被提名候选篇一条(ask=题干)。后者保证保险多产品题每篇都召回。
2. **两腿路由(≤2 篇/query)**：
   - 硬信号(位置词 第N份/前者、文档名 fc_text_00X) → 直接钉篇；
   - 聚合词(均/都/各) → BM25 top-2(跨篇核)；
   - 其余 → 文档级 BM25 相对阈值(篇分≥0.4×最高分)，单实体独高=1篇、双实体=2篇；
   - **路由只吃选项文本，绝不掺题干**(题干跨多篇会把所有选项拽向同一篇——res_a_009 的 bug)。
   - 实体拆分(每提名篇一条)兜 N>2 产品(保险排序题)。
3. **检索**：每篇各取 top-8 + 邻块回填(small-to-big)。检索 query 可带题干(篇已定，无跨篇污染，反而帮定位条款)。
4. **证据池标签用产品/主体名(doc_identities)而非不透明 doc_id** → 模型能把证据归到对应选项(治保险"哪个产品"题欠选)，ins 7→10、fin +6。
5. **领域 prompt**(BASE+DOMAIN+FORMAT，复用 legacy reasoner 文案)，一次答题逐项判真假。

**分域(新 vs legacy)**：fc 12/14、fin 15/9、ins 10/10、reg 16/14、res 17/17。
**剩余**：fc/ins 的"均/全部"过选 + subtle 欠选(ins_a_019 漏 D"无息退还全部")属推理层；gpt-oss 有 run 噪声，换强模型绝对分更高。
**注**：legacy 已删(本次未保留)，loop.py 留作 eval 检索测试；旧 agentic 诊断 eval 脚本(decompose_route/judge/miss_*/ab_decompose/decompose_eval)已删，新评分入口 `eval/score_dev.py`。
