# AFAC 多模态金融文档解析 —— 方案大纲

> 赛题：超长/超大金融文档截图 → 完整高保真 Markdown / HTML 表格
> 唯一可用大模型：FinixDoc-VL API（不可微调、不可替换）；可集成 <10M 参数、纯 CPU 的本地辅助模型
> 评分：`Overall = [(1−文本编辑距离)×100 + 表格TEDS + (1−阅读流编辑距离)×100] / 3`

---

## 0. 核心判断

- **API 是所有队伍共享的固定底座** → 全部差异化空间在 **预处理 + 编排 + 后处理纠错**，不在模型本身。
- 训练集 200 张带 GT（LONG 100 + TABLE 100），A 榜 100 张（LONG 50 + TABLE 50）。
- **A 榜分布与训练集高度一致** → 训练集上调好的切块/纠错参数可直接迁移。

|---|---|---|---|---|---|---|
| 训练-LONG | 100 | 1500~1508 | 3万~19万 | 46~287 | 20~128 | 纯 Markdown（`#`~`######`+段落），中位 1.6万字符 |

**两类图边界清晰，必须分两条流水线：**
- **LONG（面条图）**：宽锁死 1500，只长不宽 → 横向切条
- **TABLE（大表）**：近正方形但超大像素 → 行带切分 / 降采样
- **「又长又宽」**：仅出现在 TABLE（训练 7 张 / A榜 2 张，最大 22928×23390）→ 触发 2D 网格兜底

⚠️ **输出格式必须对齐 GT**：表格输出 `<table>` HTML，长文输出 Markdown 标题。错格式直接崩 TEDS / 编辑距离。

## 2. 系统架构（按图路由）

```
输入图 ──► 分类器(宽高比/尺寸,纯规则) ──┬─► LONG 流水线
                                        └─► TABLE 流水线
LONG 流水线：
  预处理(去噪/二值化/去倾斜) ─► 横向切条(2~3k px, 重叠~300px)
  ─► API 逐条识别 ─► 序列比对去重拼接 ─► 标题层级栈校正 ─► .md

TABLE 流水线：
  if 宽 ≤ API上限:  行带切分(整行宽) ─► 逐带 <tr> ─► 首尾拼接
  else (又长又宽): 2D 网格切分(行列双向重叠) ─► 坐标系重组
  并行兜底: 等比降采样整图识别(无接缝)
  ─► 结构验证器纠错(列数/行号/数值平滑性) ─► <table>
```

## 3. 关键工程痛点 → 解法

| 痛点 | 触发 | 解法 |
|---|---|---|
| OOM/超时 | TABLE 最高 3.87 亿像素 | 切块后送 API；`calibrate.py` 二分标定 API 单次最大尺寸，作为所有切块上限 |
| 视觉长上下文受限 | LONG 高达 19 万像素 | 横向切条，每次只看一小段 |
| 接缝重复/截断 | 重叠区被识别两遍 | 切块带 ~300px 重叠 → 序列比对（Needleman-Wunsch / Myers diff）锚定去重 |
| 标题层级/阅读流 | 错行目录、跨块标题、多栏 | 拼接后全局后处理：标题层级栈校正 + 轻量版面分析(XY-cut)定阅读流 |
| 「又长又宽」 | TABLE 22928×23390 | 行带优先（永不水平切断单元格）；超宽→2D 网格 + 表头/行号坐标锚定；降采样整图兜底 |

## 4. API 不准的应对（四层，由易到难）

1. **错误画像（第一步）**：在 200 张训练图上跑 API，逐字 diff GT，分类统计错误类型（漏字/重字/数字错/串列/层级丢）。不测量不优化。
2. **输入侧优化**：切片粒度调优 + 二值化/去噪/对比度/去倾斜 + 表格留白边。性价比最高。
3. **冗余多视角投票**：重叠区每段看 2 遍 + 多尺度交叉验证 → 字符级投票降随机错。不引入第二模型，合规。
4. **结构先验验证器纠错**：精算表数值沿行/列平滑单调 → 离群数字=大概率 OCR 错 → 裁出重查（targeted re-query）或标记。⚠️ 严禁幻觉，只动高置信结构错，绝不臆造文本。

## 5. 技术亮点（差异化 / 可讲故事）

| 技术 | 性质 | 作用 |
|---|---|---|
| Agentic 自纠错闭环（检测→重查→验证） | 较新 | 命中赛题"感知/切块/重组/去重/纠错"五大能力 |
| 多视角 Self-Consistency 投票 | 新（借 CoT self-consistency） | 重叠/多尺度冗余 + 字符级投票降随机错 |
| 结构先验验证器（数值平滑性当 verifier） | 新且有金融特色 | 免训练揪 OCR 错，核心差异化点 |
| 序列比对锚定拼接（NW / Myers diff） | 现代长文 OCR 标配 | 接缝去重，比"找重复子串"鲁棒 |
| TEDS-aware 树结构重组 | 现代表格识别 | 按网格坐标重组，直接对齐 TEDS |
| 轻量版面分析阅读流（XY-cut / <10M） | 经典思想+合规实现 | 多栏排版定阅读顺序，合规复刻 MinerU/Marker 思想 |

## 6. 代码结构


## 7. 落地顺序（地基优先）

1. **`evaluate.py`** —— 没有本地三指标复现就无法迭代（最优先）

5. TABLE 流水线（行带+结构纠错）→ 攻 TEDS
6. 「又长又宽」2D 兜底 + 降采样对比实验（在那 7 张训练硬图上实测谁高用谁）
7. 全流程联调 + A 榜提交 + 按榜单反馈迭代

### ⭐ 关键发现（error_profiling，2026-06-13）—— 决定整体可行性

1. **API 单次输出封顶 ~10–12k 字符**（无论图多大）。
   → **每表所需调用数 ≈ ceil(GT字符 / 10k)**，这才是 call 数的真正驱动，不是像素。
   → 证据：639k 字符的巨表整图只回 273 字符（降采样到不可读直接放弃）；分 8 带每带 ~9k。

2. **GT 字符分布极偏**（TABLE）：min 5k / 中位 74k / 均值 134k / 90% 425k / **max 639k**。
   - 中位表 ≈ 8 calls；90 分位表 ≈ 43 calls；巨表 ≈ 64 calls。
   - 50 张测试表总计 ≈ **694 calls**（LONG 仅 ~89 calls）。

3. **并发 ≥16 路无限流**：16/16 成功，延迟仅 10→13s。
   → **5 userId 不是并发上限**（单 apiKey 也能多路并发）。
   → 16 路并发下全测试集 ≈ **45 min，远低于 3h 预算。预算风险解除。** ✅

**策略定论**：
- 切块目标 = 每块输出 ≈ 顶满 10k 字符 **且** 分辨率仍可读（避免 API 内部降采样糊掉小字）。固定 ~30s 安检开销 → 宜「少而满」的切块。
- 宽表（>~8000px）宽度方向会被内部降采样 → 必须列向也切（2D），否则小数字读不准。
- 巨表（>400k 字符，约占 10%）是 call 大户，但 16 路并发仍可承受。

### ⭐⭐ 决定性发现：TABLE 必须 2D 原生分辨率分块（2026-06-13）

**API 内部分辨率上限 ≈ 1500px**。行带分块只切高度、保留全宽 → 宽度被内部降采样 → 小数字糊 → 严重漏读（中位表 16 行带仍只 TEDS 0.49、读到 62k/74k）。

**改用 2D 原生方块分块（tile≤1500px）→ 内容近乎全捕获**：

| tile 尺寸 | 中位表分块数 | token 召回 |
|---|---|---|
| **1500px** | 20 | **0.998** ✅ 锁定 |
| 2000px | 12 | 0.920 |
| 2400px | 6 | 0.808 |
| 1100px | 35 | 0.979（碎得多反而降）|

**TABLE 流水线定论**：
1. 按 **1500px 原生方块**（含 ~150px 重叠）做 2D 网格切分 → 每块 API 读 → 内容召回 ~99.8%。
2. **剩余核心工程 = 2D 重组**：把碎块按网格坐标拼回完整 `<table>`，并去除重叠/边界重复读（实测非重叠切分 pred_len 127k vs GT 74k，约 1.7× 重复，重组必须 dedup）。这是把「99.8% 内容召回」转成「高 TEDS」的关键，也是差异化所在。

### 预算定论（tile=1500，2D 切分）
| 并发 | 50 表(~1618 tiles) | + LONG | 对 3h 预算 |
|---|---|---|---|
| 16 | ~101min | ~110min | ✅ 有余 |
| 24 | ~67min | ~75min | ✅ 宽裕 |
| 32 | ~51min | ~60min | ✅ 很宽裕 |

→ tile=1500 的精度选择**预算可承受**，并发可从 16 起，必要时上探 24–32。

2. **重叠锚定对齐**：列/行各留 1 重叠单元格，用重叠内容做行对齐 + 去重（稳，但代码量大）。
3. **密表特判 + 接受部分分**：先保住占多数的中小表（0.8–0.95），密表给可接受的次优结构。
4. 改进 evaluate 的 read-order/teds 口径，确保本地分与线上一致后再深挖。

### ⭐ 关键约束确认 + 病态归因（2026-06-13，实测）

**A. API 不支持 prompt 控制**（已测）：传 `prompt`/`query` 报"无法查询智能体配置"，
`text`/`instruction`/`system` 超时，`question` 被忽略。
→ **FinixDoc-VL 是固定的图→markdown 黑盒，无法指示输出格式/行结构/空格处理。
   所有结构控制必须在我们这边做。**

**B. 密表三种病态 → 同一个根因**：
- **差 1 行**：切点没落在行网格线上 → 边缘半行取舍不一致。（"±1 容忍"是 overfitting，弃用）
- **展平幻觉**（1行×819列）：又宽又矮的薄条 / 含半行的 tile → VLM 看不出行边界 → 全塞进一个 `<tr>`。
- **根因统一**：**切点必须严格落在检测到的行/列网格线上**，每个 tile 含整数行整数列 →
  同一 band 各列块天然同构（不差行、不展平）。

**C. 空/乱区 → 不调 API，自己填**：
  既然不能 prompt，**用墨量投影预判空白 tile → 跳过 API → 按已知网格填空 `<td></td>`**。
  既免幻觉又省调用。

**D. 部分表非扁平网格**：含标题文字 + 多级表头（如 男性/女性 × 交费方式）+ 可能多子表，
  需把标题/表头区与数据区分开处理（后续）。

### TABLE 重写方向（落地中）
1. `slicer_table`：**严格在网格线处切**（每 tile 整数行列）+ **空白 tile 预判跳过**。
2. `stitch_table`：按内容（首列标签/网格骨架）对齐各列块，弃用 ±1 hack；空白 tile 填空格。

### 重写结果（2026-06-13）

- ❌ **"用检测骨架强制行数"是错的**：行/列线检测不够准（83列 vs 真值70），硬套行数把
  好 tile 也搅乱，spread 均值反而从 0.38 跌到 0.09。**已回退**为
  "中位行数 + 退化块填空"，恢复到均值 0.38。
- **当前 TABLE 实况（blank-skip + 中位合并）**：
  | 表 | GT | TEDS |

  | 32799493 | 5k | 0.78 ✅ |

### 攻密表 TEDS（2026-06-14）—— 拿到 +0.09 真实增益

**逐层定位（实测，非猜测）**：
