## 1. 核心判断

FinixDoc-VL 是所有队伍共享的固定底座，不可微调、不可替换，且**不接受任何文本 prompt**（实测传 `prompt`/`query` 返回"无法查询智能体配置"，`text`/`instruction` 超时）。它就是一个图 → Markdown 的黑盒。

这决定了全部差异化空间在**切什么、怎么切、切多大、结果怎么校验与修复**，不在模型本身。我们的方法论由此确定：**把结构决策权从模型手里收回到代码里**——几何负责定位（切在哪、有几行几列、哪里是空的），模型只负责回答"这块里是什么字"。凡是需要模型"自己记住位置"的任务，都会在密集重复内容上失稳；凡是位置由代码给定的任务，对应的错误类别就结构性地不可能发生。

两类图痛点完全不同，走两条独立流水线（类别由官方目录给定，不靠长宽比猜）：

| 类型 | 数量 | 尺寸 | 核心痛点 |
|---|---|---|---|
| LONG 面条图 | 训练 100 / B 榜 50 | 宽锁死 1500，高 3万–19万，长宽比 20–128 | 视觉长上下文受限、接缝重复与截断、标题层级 |
| TABLE 大表图 | 训练 100 / B 榜 50 | 近正方形，最高 22928×23390（3.87 亿像素） | 密集网格跳行/复读、多子表、多级表头 |

## 2. 推理资源与时间

**不依赖 GPU**。全流程 CPU + 远端 API + 一个 5.27M 参数的本地 CPU 小模型。

| 项 | 配置 |
|---|---|
| 硬件 | 24 核 CPU / 62GB 内存 / 无 GPU；建议 ≥ 8 核、≥ 16GB |
| 软件 | Python 3.11 / Linux；依赖见 `requirements.txt`，无编译扩展 |
| 磁盘 | ≥ 2GB（API 结果与本地 OCR 结果的落盘缓存） |
| 并发 | 图级 6 进程 × 图内 32 线程；API 侧限流自动退避 |

**推理时间**：B 榜实测两个半边各约 **10 分钟**（50 张 LONG / 50 张 TABLE，并发 32）。引入本地小模型做 TABLE 残差重读与 LONG 几何定级后，两侧均略有增加——几何定级冷跑约 5s/张、残差重读只在不合格 tile 上触发。**全量 100 张按 30 分钟预估，留足余量也在 1 小时以内**，远低于 3h 上限。

真实耗时的主要变数是 API 侧负载而非本地计算：过载时服务端会"收下不回"，因此 `API_TIMEOUT` 设为 40s 快速放弃、靠缓存重跑补失败，而不是死等。

调用规模参考（100 张）：LONG 约 754 次 + TABLE 约 2426 次，空白 tile 预判跳过省下 1125 次调用。

**未使用 ensemble**：全流程只有 FinixDoc-VL 一个 VLM，无多模型投票、无多次采样融合。所有增益来自几何前处理与结构后处理。

## 4. LONG 流水线

**① 切**——水平投影求每行墨量，在**行间空白带**下刀，而非等高裸切。切点落在字行之间，接缝处不出现半行残字。目标条高 `target_h = 5000px`（实测延迟随高度线性：H1500→8s，H5000→13s，H10000→27s，5000 是延迟与条数的平衡点）。

表格禁切区：条带内若检测到表格（竖线按"线"计数 ≥3 条，逐带独立核验），切点让路避开——但**带高超过 `target_h` 的表不让路**。这条约束是逐项隔离实验逼出来的：早期版本对放不下的表也让路，结果顶高切点、造出短条带并连锁位移，单篇 read 从 99.0 掉到 65.1；TEDS +0.64 被 read −0.37 抵消为净负，加约束后才转正。

**② 读**——各条带并发送 API，按图像内容 SHA1 落盘缓存。

**③ 拼**——接缝处理两类情况：跨条重复行去重；长表格中部没有空白带、切点必然落在表内，上条被收口成 `</table>`、下条重开 `<table>`，此处做跨条表格重连，并回收被读到表外的孤儿单元格前缀。

**④ 文本层级校正**——模型按条带识别，`#` 是局部判断，拼成整篇后同一编号序列常在条带边界被重置。`heading_norm` 用**栈模型**做相对定级：编号连续性判同级/下钻/回上级，回到已出现过的编号序列时用该序列的**历史层级**而非相邻层级 ±1，修复"深层游走后回浅层"的漂移。另有三条针对性处理：56% 文档的大标题被模型拆成无 `#` 的多行普通段落 → 合并提升为 L1；目录条目被吐成 `* 1.1 …` → 转为标题；表内满宽横幅行的 `colspan` 归一（依训练集 GT 主流写法，102 例用 colspan、5 例用裸 td）。

**⑤ 几何层级定级**——`geom_heading` 是 LONG 路的最后一步，也是唯一回到**原图**做全局裁决的一步。层级本质是排版信息，前四步都只能从文本推断。这里回原图逐行量标题的**字号**（行内 core 高度，相对本文正文中位、每文档独立）与其上下的**淡横线**：淡横线上方 = 章级 H1；无编号中段标题按字号判，≥ 正文中位 1.25× 为真篇名保留 H1，否则判为模型误报删除。必须放在拼接之后——整篇拼好了字号才有全局可比性。逐行识别用本地 PP-OCRv6s，结果按图片名缓存。

## 5. TABLE 流水线

**① Stage I 几何裁剪**（纯几何，不调模型）——先剥离表外 furniture（页眉/页脚/水印/页码，判据是"矮 + 窄 + 非最大连通块"），再切分并排子表。

子表切分的两条判据都是第一性的，替掉了早期的魔数"段数 < 4"：

- **缝高 ≥ 2× 行缝基准**：连续白线（整行墨 < 0.3% 宽）成"白带"，白带高度中位数即行缝基准。实测真子表缝是行缝的 2.5–10 倍，单表内空行的缝 ≈ 1 倍，中间 [1.1, 2.5] 是空带，阈值 k=2 干净分开。
- **缝内无框线竖线贯穿（≤2 条）**：稀疏表底部的空行，边框与列线仍连续穿过（实测某表底部 9 条竖线贯穿 = 仍在表内）；真子表缝处框线断开（实测 0 条）。

这一步的重要性来自评测口径：`table_teds` 按出现顺序**逐表 index 配对** GT 与 pred，把 N 个子表读成 1 个大 table 时只能配上 GT[0]、其余全部计 0。**段数必须精确等于 GT，差 1 就全盘错位归零**——所以顶部标题段必须剥离（任何送进识别的段都会被包成一个 `<table>`，标题段会凭空多出 1 段）。

**② Stage II 骨架 OCR**——严格在网格线处切 tile，每个 tile 含整数行整数列。这条约束直接根治两种密表病态：切点没落在行线上 → 边缘半行取舍不一致（差 1 行）；又宽又矮的薄条 → 模型看不出行边界 → 全塞进一个 `<tr>`（曾出现 1 行 × 819 列的展平幻觉）。tile 上限 25 行 × 15 列。

墨量极低的空白 tile **直接跳过不送模型**——既省调用又免幻觉（不能 prompt，就用墨量投影自己预判并填 `<td></td>`）。

小字 tile 先上采样：判据 `cell_edge = √(去 margin 面积 / (行×列)) < 40px`，倍数 `clamp(75/edge, 1, 3)`（目标格边长 75px）。这里有个反直觉的实测结论：**密集小字 tile 在原分辨率下 API 反而又慢又错**（单 tile 1× 耗时 181s 且读崩成行幻觉/列漂移；上采样 2.58× 只要 45s 且读对）。上采样是"又快又准"的双赢，不是"提分但变慢"的取舍——模型在密集小字上会反复挣扎走慢路径。

核心是**一把尺、一个判定、一个修复**：

- **尺**：墨迹几何 `cell_ink ∪ cell_gray` 给出每个 tile 的期望——哪些行有内容、每行哪些格有墨。
- **判定**：零容差**占位恒等**——非空行数 == 期望行数，且每行逐格满足"非空 ⟺ 有墨"。禁众数、禁 ±1 容差。这个判据是演化出来的：早期用"列数上界 ≤ nc"留了窗口，口吃值藏进区间（某 tile 538 格幻读、96% 与左邻重复）；改用"宽度恒等"仍是占位图的一维投影，漏掉"前段/中段占位缺失"（某 tile 13×7 的方洞：API 行前 7 格空、右侧有值，宽度照样相等）。占位恒等是完全体，宽度恒等只是它的推论。
- **修复**：唯一动作——不合格 tile 整块回落本地 PP-OCRv6s **逐格重读**。行列位置由几何骨架给定，模型只回答"这格里是什么"，位置控制权收回代码，**计数类错误（爆行/漏行/行跳读）结构性不可能发生**。单调重复区（如 `3000` × N）恰恰是 API 最易失稳、逐格识别最容易的输入。本地模型确定性输出，重放天然稳定。

**③ Stage III 2D 重组**——tile 结果按全局行列坐标装配成完整 `<table>`，做列校准与 colspan 审计。跨列表头按内容簇分段发 `colspan`；表头结构按"列号行"锚定重建（前 3 行里连续整数 run ≥ 5 的行）；编号序列按局部连续段补齐（只补 0–9，横向前 3 行、纵向前 4 列）。

## 6. 参数设置

| 参数 | 值 | 依据 |
|---|---|---|
| `MAX_CONCURRENCY` | 32 | 16 为官方标称上限，实测 32 吞吐更高；限流自动退避且不污染缓存 |
| `POOL_PROCS` | 6 | 图级进程并行绕 GIL，几何计算是 CPU-bound |
| `API_TIMEOUT` / `API_RETRIES` | 40s / 3 | 过载时服务端"收下不回"，40s 没回等也白等；快速放弃 + 靠缓存重跑补失败 |
| `DEGEN_RETRIES` | 1 | 复读退化是确定性的（同条带删缓存连打 5 次 5/5 复现），多打纯浪费 |
| LONG `target_h` | 5000px | 延迟随高度线性，5000 是延迟与条数的平衡点 |
| LONG `MIN_RULES` | 3 条 | 表格至少有左边框 + 列线 + 右边框；2 条会把两栏排版误判成表 |
| TABLE tile 上限 | 25 行 × 15 列 | 单变量隔离实验定论（行 20→25 回退过一次） |
| 上采样判据 / 上限 | `cell_edge < 40px` / 3× | 目标格边长 75px；二维 cell 面积能抓"列稀行密"的表 |
| 子表缝高倍数 k | 2 | 真缝是行缝的 2.5–10 倍、空行缝 ≈ 1 倍，k=2 位于干净间隔内 |
| 缝内竖线贯穿上限 | 2 条 | 真子表缝框线断开（实测 0 条），表内空行仍有 9 条贯穿 |
| `BIN_INK` / `BIN_FAINT` / `BIN_LINE` | 128 / 180 / 170 | 正文是浓墨，框线与淡标题常在灰度 130–180，分严松两档 |

所有阈值都是几何/统计维度的通用判据，无针对特定图片的分支或白名单。

## 7. 从 baseline 到最优

**Baseline（第一版可跑通的流水线）**：LONG 等高裸切 + 直接拼；TABLE 行带切分（只切高度、保留全宽）+ 首尾拼接。

第一个决定性发现就否掉了 TABLE 的 baseline：**API 内部分辨率上限约 1500px**。行带切分保留全宽 → 宽度被内部降采样 → 小数字糊掉 → 中位表切 16 个行带仍只有 TEDS 0.49、内容只读到 62k/74k 字符。改用 **1500px 原生方块 2D 切分**后内容召回从 0.49 直接到 **0.998**（2000px 为 0.920、2400px 为 0.808、1100px 反降到 0.979——碎得多反而降）。

至此问题转化为：内容已经 99.8% 读回来了，**如何把碎块拼回正确结构**。后续全部工作都在这条主线上。

### 7.3 两个转折点

**指标本身的 bug（第 9 项，+1.7）**。旧的本地 `teds_grid` 用"行签名精确匹配"对齐行，但预测行因 OCR 或列数差异**永远不等于** GT 行签名，实际退化成按位置配对；行数不等时，缺行或多行之后整体错位，距离暴增。某张 +2 列、内容完美的表被打成 0.37，修复后是 0.911。改成带状行级 DP（替换代价 = 单元格级编辑距离，对齐 APTED 口径）后 GT-vs-GT 仍精确等于 1.0。

教训是**先验证评测指标本身正确，否则可能朝错误的方向优化**——修复后重新分桶，原先占 17 张的 "cell_misalign" 桶大部分是指标假象。

**评分口径的实验证伪**。我们一度认为标题层级是 LONG 最大失分点。用一次隔离提交钉死了这个假设：只改标题层级，13/50 篇变化、**627 个标题的级数改变（占 B 榜 long 全部 2763 个标题的 22.7%）、非标题正文一字未变** → **线上分数完全不变**（前后均为 40.31）。且这 13 篇里有 6 篇是混合位移（父子层级关系真的被重排），不只是整体平移。

结论：`#` 根本不进评分，"层级关系"同样不计分。这个零结果的分辨率是够的——若阅读流是块级且计 `#`，627 个标题约占 4.2% 的块，应当带来约 0.63 分的变动。这次实验让我们把后续 LONG 的投入从层级转向真正的失分源：残余失配块里 **41.4% 是 OCR 近似字**（`9→?` 125 处、`×→x` 89 处、中文引号→直引号 81 处），**29.4% 是内容在 GT 中原样存在、只是断行位置不同**。

## 8. 否决方案记录

负结果同样是结论。以下方案都有数据支撑，记录在案以免重复投入：

| 方案 | 结果 | 原因 |
|---|---|---|
| 用检测到的网格骨架**强制**行数 | 均值 0.38→0.09，回退 | 行列线检测不够准（83 列 vs 真值 70），硬套把好 tile 也搅乱。**检测当软先验可以，当硬约束不行** |
| 裁剪尾部空白列（三角表） | 净均值 0.47→0.45，回退 | raggedness 逐表而异：帮了 ragged 表（0.25→0.36）却伤了保留空 td 的表（0.89→0.83），无通用规则 |
| 竖线缝拆分（有框多子表） | 79.2→79.0，弃用 | 过切 |
| band 行数用 max 恢复截断行 | 79.9→79.8，回退 | 恢复的是空行，内容已丢 |
| 5 种子表检测（固定 gap / 覆盖度 / 自适应 / API 降采样 / 列指纹） | 全不稳健 | 要么欠切要么过切，**过切会打烂当时 74 张已达 0.7–0.95 的单表**；根因是三角表自然收窄与真子表边界用投影无法区分 |
| 几何分表（LONG） | 弃用 | 全训练集只 1 篇真损失，上限 +0.93 TEDS，却要动全局表格装配（45/48 篇现在是对的） |
| 全局层级偏移校正 | 两个候选端到端都更差 | 26/100 篇整篇差一级、上限 +11，但常数锚点与最浅归一 L1 都失败，没有原理杠杆就不硬改 |
| 全半角标点归一 | 全部亏 | NFKC 口径下不计分；若计分则占残余编辑量 56.8%，但所有规则（全转全角/半角/汉字紧邻/文档多数派）在字级与块级下都是负收益——GT 中汉字紧邻标点本身有 17.6% 是半角 |
| 截断块重读 | 停用 | 实测约 3h/全集，违反时间预算 |
| 列校准投票采纳 | 废除采纳，只留审计 | 被均匀口吃骗票（三票 13→14→产生空列与幻读列） |

## 9. 新颖点与思考

**① 把"模型不擅长的"变成"结构上不可能发生的"**。密表跳行/复读的根因是自回归解码依赖自己的输出史追踪表内位置，重复内容摧毁这种追踪。业界常规做法是加容错（±1 行、投票、多次采样）。我们的做法相反：用几何骨架把行列位置钉死，让模型只做"这格是什么"的无状态问答，于是计数类错误的**发生条件本身**被消除。这也是本方案唯一用到本地小模型的地方——它不是为了比 API 更准，而是为了提供一个"位置由代码控制"的执行体。

**② 零容差判定优于容错判定**。"一把尺、一个判定、一个修复"的架构，最终删掉了七台各自处理一类病态的"专用修理机"（约 370 行代码）。容错阈值会留出窗口让错误藏进去（口吃值藏进 `[inkw, nc]` 区间），而占位恒等判定没有窗口——要么完全对，要么整块重读。**判据越严，抢救逻辑越少**。

**③ 不能 prompt 反而催生了更强的前处理**。因为无法告诉模型"这块是空的别编"，我们必须用墨量投影自己预判空白 tile 并跳过——结果既省了 1125 次调用又根除了一类幻觉。约束倒逼出的方案比"能 prompt"时会写的方案更鲁棒。

**④ 上采样是双赢而非取舍**。密集小字在原分辨率下模型又慢又错（181s vs 45s），这个反直觉现象说明 VLM 在超出其有效分辨率的输入上会反复挣扎。把输入调整到模型的"舒适区"，精度与延迟同时改善。

**⑤ 隔离实验是必需品，不是奢侈品**。多项改动打包测试会被互相抵消骗过去——LONG 的表格禁切区单独算是净负（TEDS +0.64 被 read −0.37 抵消），因为 TEDS 只覆盖 48 篇而 read/text 覆盖全部 100 篇。每次提交只动一个变量，线上分数的变化才能归因。

**⑥ 先验证仪器再优化**。指标 bug 让我们在错误的方向上走了几轮；层级零结果实验则用一次提交排除了一整个方向。**在评测口径不透明的比赛里，设计能证伪的隔离实验，比多写几条规则更值钱**。

## 10. 未来可拓展方向

**近期可做**：

1. **字符识别精度**。残余失分的 41.4% 是 OCR 近似字（`9→?`、`×→x`、全角引号），这类错误对 API 而言是系统性的。可用本地小模型做**差异检测**而非全量替换：只在本地与 API 结果分歧的格上走仲裁，成本可控。
2. **断行位置对齐**。29.4% 的失配块内容在 GT 中原样存在、只是分行不同。这不是识别问题而是排版还原问题，可用行间距的统计分布判断"同段续行"还是"新段落"。
3. **blank-and-measure 标定权重**。提交"剥掉全部 `<table>` 的版本"与原版对比，直接测出 TEDS 在总分里的实际权重与去向，让本地指标与线上对齐——目前本地可见余量只有线上缺口的三分之一，约 3.5 分在任何本地指标里都看不见。

**中期方向**：

4. **每 tile 锚定"首行表头 + 首列标签"**。切片时给每个 tile 拼上表格首行与首列，使其成为自洽子表。一招可治四类问题：行折叠（标签使每行非空）、列折叠（表头使每列非空）、列爆炸（按表头去重跨带重复列）、行列对齐（按标签/表头当键）。实测证据是带标签列的 tile，API 会保留空数据行。代价是每 tile 多一行一列。
5. **结构先验做验证器**。精算表的数值沿行/列通常平滑或单调，离群数字大概率是识别错误，可裁出重查。需严格限定只动高置信结构错，绝不臆造文本。
6. **版面分析扩展到多栏与跨页**。当前多栏处理依赖几何投影，对图文混排、跨页表格延续等复杂版式仍有提升空间，且可在 10M 参数预算内实现轻量版面模型。

**方法论层面**：本方案的核心是"几何定位 + 模型识别 + 零容差校验 + 确定性兜底"的四段式。这个模式不限于文档解析——任何"大模型在长序列上会丢失位置追踪"的任务（长表格、长列表、多轮结构化抽取），都可以用同样的思路把位置控制权交还给代码。

## 11. 合规声明

- **大模型**：全工程唯一的 VLM 接口是 FinixDoc-VL API，调用点集中在 `src/common/api_client.py`（两处 `requests.post`），无任何其它第三方模型 API、SDK 或网络地址。
- **Prompt**：该 API 请求体只有 `userId / apiKey / fileName + 图片文件`，不接受文本 prompt 参数，因此本方案没有 prompt 配置文件。
- **本地小模型**：`PP-OCRv6_rec_small.onnx`，**5.27M 参数**（< 10M 上限），CPU + onnxruntime。同引擎载入的 det/cls 模型调用时均置 `use_det=False / use_cls=False` 不参与推理，三者合计也仅 7.72M。模型随 `rapidocr` wheel 安装，运行期不联网。
- **无结果硬编码**：不含针对特定测试图片的固定输出、白名单或 uuid 分支。
- **一键复现**：`bash run.sh` 单条命令产出完整 `submission.csv`。
